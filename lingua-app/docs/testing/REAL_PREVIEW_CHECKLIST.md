| 项目 | 测试部署 | 正式部署 |
|---|---|---|
| 应用代码 | 同一版本 | 验收后的同一版本 |

本轮仅改文件，没有运行正式数据库 SQL、配置真实密钥或发布网站。
新功能默认仍关闭。没有游客额度重置按钮、自动补充额度、管理员无限额度或跳过真实登录的演示入口。

## 开始前的配置

1. 若尚未执行第一阶段迁移，按 PHASE1_SETUP.md 执行原 SQL 和只读检查；已成功执行的不需要重新建表。本轮不新增 SQL。
2. 在测试部署的服务器环境中设置：

```dotenv
MONETIZATION_MODE=test
MONETIZATION_TEST_EMAILS=你的专用测试邮箱
MONETIZATION_TEST_USER_IDS=
APP_ORIGIN=https://你的固定测试域名
GUEST_SIGNING_SECRET=稳定保存的至少32字符随机密钥
```

3. 沿用现有项目的 Supabase URL、anon key 和服务端 service_role key；这些值只在部署平台配置，不要发到聊天或提交到仓库。
4. 测试站的邮件回调地址加入 Supabase Auth 允许列表，不替换正式 Site URL 或移除正式回调。使用 App 现有邮件登录流程完成验证。
5. 核对真实 AI 配置：文本服务沿用既有 Gemini／Vertex 凭据（GEMINI_API_KEY 或现有 Google 服务账户方式）；翻译与云语音沿用 GCP_API_KEY。不要为这次测试切换模型或教学提示词。
6. 配置改变后重新部署测试站。不要把测试配置应用到正式域名。

本项目仍有正常的教材素材和服务故障备用行为；看到素材卡片不能证明 AI 服务已验证。应实际完成翻译、语法、写作反馈、对话与播放检查。真实 AI 调用使用真实服务，可能产生其正常费用。

## 自动测试与真实验收的区别

- 数据库／接口测试执行真实迁移和事务，但使用本地 PostgreSQL 兼容引擎与本地 Supabase 请求适配器。
- 浏览器测试在本机以模拟接口检查游客、登录继续、确认重试和多标签页同步。
- 上表必须在固定测试部署和真实服务上手工执行；邮件可达性、线上配置、真实多连接竞争尚不能由上述本地检查证明。
- 不提供自动清除测试账户或测试课程的公开接口。不使用日常账户，不修改正式用户额度。
